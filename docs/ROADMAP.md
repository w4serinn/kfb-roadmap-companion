# ROADMAP

## プロジェクトの目的(確定)

Kawaii Future Bass作曲学習ロードマップ(1年計画)を実際に走り切るための支援サイト。
音楽制作アプリの代替ではなく、継続と理解の橋渡し役に徹する。

## 非ゴール(確定・変更しない)

- 実際の作曲・DAW操作そのものの代替(FL Studio / Vitalの役割はそのまま)
- 音源ファイルの管理・DAWプロジェクトのバックアップ
- SNS共有や他者との比較機能(「比較対象は先週の自分だけ」という方針と矛盾するため)
- AIによるメロディー・楽曲の自動生成(レイヤー4は本人が思いついたメロディーの
  採譜支援であり、AIが代わりに作曲する機能ではない)
  - レイヤー5(コード候補提示)は例外的に許容する。ダイアトニックコードとの
    構成音一致という決定論的な照合ロジックであり、創作的な自動生成ではない。
    候補は必ず複数提示し、単一の正解を返す形にはしない

## フェーズ(確定・優先順位)

1. **フェーズ1(完了)**: 進捗レイヤー — 週/日次チェックリスト、挫折対策の仕組み
   (復帰表示・合格ライン表示・バージョン番号)
2. **フェーズ2(現在)**: 記録レイヤー — 週末チェックイン、タスクごとの一言メモ欄
3. **フェーズ3**: 耳コピ支援レイヤー — キー選択・ダイアトニックコード表示・
   コード/リズムのプレビュー再生・答え合わせへの橋渡し
4. **フェーズ4**: メロディー起こし支援レイヤー — 鼻歌の録音・自己相関法による
   音高解析・音名への変換・再生確認(単音前提、リズムは目安程度の精度)。
   フェーズ3とWeb Audio APIの技術基盤を共有するため、並行または直後の着手も可
5. **フェーズ5**: コード候補提示レイヤー — メロディー音とダイアトニックコードの
   照合による候補提示(必ず複数候補、単一の正解にしない)。フェーズ4完了後、
   レイヤー4で捕まえたメロディーと連携させる想定

フェーズを超えた先取り実装はしない(evolve/SKILL.md参照)。フェーズが進むタイミングは
人間が`docs/ROADMAP.md`のこのセクションを書き換えることで示す。

## 機能一覧と進行状況

各機能はS/Mサブタスクに分割し、数サイクルかけて完成させる。

### 0. プロジェクト基盤(セットアップ) [status: 完了]

### 1. 進捗トラッカー(既存チェックリストの移植) [status: 進行中]

フェーズ1の機能一覧タスクが尽きたため、既存実装の実データ保全という観点で
新規タスク候補を追加。1年分の進捗が`localStorage`のみに保存されており、
ブラウザデータ消去・端末変更で失われるリスクがあるため、データ可搬性を
補強する(新しいレイヤーの追加ではなく、既存の進捗トラッカー機能の堅牢化)。

- [ ] 全チェックとバージョンメモをクリアする「進捗をリセット」ボタン
      (誤操作防止の確認ダイアログ付き)

### 2. 挫折対策の仕組み [status: 完了]

### 3. 記録レイヤー(週末チェックイン・一言メモ) [status: 未着手]

DESIGN.mdレイヤー3。「今週は制作/理論/耳コピ、どのくらい触れた?」を数値ではなく
感覚(3段階)で聞く軽いチェックインと、タスクごとの一言メモ欄。日記ほど重くしない。

- [ ] 週末チェックインのデータモデル・ロジック(`assets/checkin-logic.js`):
      週(ISO週番号など)ごとに「制作/理論/耳コピ」各カテゴリの3段階の感覚
      (例: お休み/ぼちぼち/がっつり)を`localStorage`(`kfb-checkins`)に
      保存・取得する純粋関数。日付から週の判定を行う部分は現在時刻を引数で
      渡せる形にしてテスト可能にする
- [ ] 週末チェックインのUI実装(3カテゴリ×3段階のボタン選択フォームを
      ページ内に表示し、選択結果を保存する)
- [ ] タスクごとの一言メモ欄(週タスク/日次ステップに紐づく自由記述欄。
      `バージョンメモ`と同様の軽量な入力欄を`localStorage`(`kfb-notes`)に保存)
